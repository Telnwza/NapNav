# NapNav — Trip Alarm: Product and Experience Design

อัปเดตล่าสุด: 20 กันยายน 2026  
สถานะ: แนวทางออกแบบสำหรับ Technical POC และ GPS MVP

## ชื่อผลิตภัณฑ์

- ชื่อหลัก: **NapNav**
- คำอธิบายต่อท้าย: **Trip Alarm**
- ชื่อที่ใช้แสดง: **NapNav — Trip Alarm**

ในโลโก้ ไอคอน และพื้นที่ขนาดเล็กให้ใช้ `NapNav` เป็นหลัก ส่วน `Trip Alarm` ทำหน้าที่อธิบายว่าแอปช่วยเตือนระหว่างเดินทาง ชื่อแอปที่ผู้ใช้เห็นและ build product เปลี่ยนเป็น NapNav แล้ว ส่วน Xcode target, module และ Bundle ID ยังใช้ `StopAlarm` อยู่เพื่อไม่ให้ signing กับชุดทดสอบเดิมสะดุด

ต้นแบบ UI: [เปิดไฟล์ต้นแบบ](ui-prototype/index.html)

## 1. แนวคิดหลัก

NapNav ไม่ควรถูกออกแบบให้เป็น “แอปแผนที่อีกตัว” แต่เป็น **ผู้ช่วยเฝ้าจุดหมายที่สงบและไว้ใจได้**

ระหว่างเดินทาง ผู้ใช้ไม่ควรต้องเปิดหน้าจอเช็กตลอดเวลา หน้าที่ของ UI คือทำให้ตอบคำถามสำคัญได้ภายในไม่กี่วินาที:

1. เปิดการเตือนไว้หรือยัง
2. เหลืออีกไกลเท่าไร
3. ระบบพร้อมเตือนหรือมีปัญหาอะไร

ชื่อแนวคิดชั่วคราว: **Calm Journey**

คำสำคัญของงานออกแบบ:

- สงบ ไม่รบกวน
- อ่านง่ายในที่มืดและบนรถที่กำลังเคลื่อนที่
- แสดงความมั่นใจอย่างตรงไปตรงมา
- ปุ่มหลักมีเพียงหนึ่งการกระทำต่อช่วงเวลา
- ไม่ใช้สีเพียงอย่างเดียวในการสื่อสถานะ

## 2. Product promise

> เลือกจุดหมาย กดเริ่ม แล้วพักได้ แอปจะเตือนเมื่อคุณเข้าใกล้จุดหมาย

ข้อจำกัดที่ต้องสื่อสารอย่างตรงไปตรงมา:

- ระยะทางและเวลาถึงเป็นค่าประมาณจากตำแหน่งของอุปกรณ์
- เสียงเตือนขึ้นอยู่กับสิทธิ์ Notification, ระดับเสียง และ Focus ของเครื่อง
- หากตำแหน่งใช้ไม่ได้ แอปต้องแจ้งสถานะ ไม่แสดงเหมือนว่ายังทำงานปกติ

## 3. Information hierarchy

### ระหว่างตั้งค่าทริป

1. จุดหมาย
2. ระยะเตือน
3. ความพร้อมของ Location และ Notification
4. ปุ่มเริ่ม

### ระหว่างเดินทาง

1. สถานะ “เปิดเตือนไว้แล้ว”
2. ชื่อจุดหมาย
3. ระยะห่างปัจจุบัน
4. สถานะสัญญาณและเวลาที่อัปเดตล่าสุด
5. ปุ่มหยุดทริป

แผนที่เป็นข้อมูลประกอบ ไม่ใช่ข้อมูลชิ้นใหญ่ที่สุดระหว่างเดินทาง

## 5. Screen design

### 5.1 Home — “จะไปที่ไหน?”

```text
┌─────────────────────────────┐
│ NapNav                 ⚙︎   │
│                             │
│  จะไปที่ไหน?               │
│ ┌─────────────────────────┐ │
│ │ 🔍 ค้นหาสถานที่         │ │
│ └─────────────────────────┘ │
│                             │
│                             │
│          MAP                │
│       • ตำแหน่งคุณ          │
│                             │
│                    ◎        │
└─────────────────────────────┘
```

พฤติกรรม:

- เปิดมาเห็นแผนที่และช่องค้นหาทันที
- ยังไม่ขอ Notification permission
- ขอ Location เมื่อผู้ใช้กดใช้ตำแหน่งปัจจุบันหรือเริ่มค้นหาใกล้ตัว
- รองรับการค้นหาและการกดค้างเพื่อปักหมุดใน GPS MVP
- ค้นหาสถานที่ได้ด้วย MapKit autocomplete และแตะแผนที่เพื่อปักหมุดเองได้

### 5.2 Destination Preview — ยืนยันจุดหมาย

แสดงเป็น bottom sheet เหนือแผนที่:

```text
┌─────────────────────────────┐
│          MAP                │
│              ◉ จุดหมาย      │
│        (วงรัศมีเตือน)        │
├─────────────────────────────┤
│ สถานีอโศก                   │
│ ถนนสุขุมวิท เขตวัฒนา        │
│                             │
│ [ ใช้จุดหมายนี้ ]           │
└─────────────────────────────┘
```

ต้องแสดงวงกลมรัศมีเตือนบนแผนที่ เพื่อให้ผู้ใช้เข้าใจว่าแอปปลุกเมื่อ “เข้าเขต” ไม่ใช่เมื่อถึงพิกัดเป๊ะ

### 5.3 Alarm Setup — ตั้งค่าการเตือน

```text
┌─────────────────────────────┐
│ ตั้งค่าการเตือน             │
│                             │
│   แผนที่ + วงรัศมีแจ้งเตือน   │
│        ● สถานีอโศก          │
│                             │
│ เตือนตอนเหลือระยะ            │
│ [ 500 ม. ] [ 1 กม. ] [ 2 กม.]│
│ [ กำหนดระยะเอง 100 ม.–5 กม.] │
│                             │
│ เสียงเตือน: มาตรฐาน          │
│ การสั่น: เปิด                 │
│                             │
│ [ เริ่มเฝ้าจุดหมาย ]         │
└─────────────────────────────┘
```

ค่าเริ่มต้นที่เสนอ: **1 กิโลเมตร** เพราะสมดุลกว่าระยะ 500 เมตรสำหรับรถที่เคลื่อนที่เร็ว แต่ต้องเก็บข้อมูลภาคสนามก่อนยืนยันเป็นค่าเริ่มต้นจริง

วงรัศมีบนแผนที่ต้องผูกกับระยะที่เลือก และขยายหรือหดทันทีทั้งตอนกดค่าระยะสำเร็จรูปและตอนลาก slider ใน SwiftUI ให้ใช้ `MapCircle(center:radius:)` เพื่อให้ขนาดสัมพันธ์กับระยะจริงบนแผนที่ ไม่ใช่ขนาดพิกเซลบนหน้าจอ

### 5.4 Readiness Check — ตรวจความพร้อม

หน้าจอนี้ปรากฏหลังผู้ใช้กดเริ่มครั้งแรก ไม่แสดง permission dialog ซ้อนกันทันที

```text
พร้อมเริ่มเดินทางหรือยัง?

✓ เลือกจุดหมายแล้ว
✓ ใช้ตำแหน่งได้
! ยังไม่ได้อนุญาตการแจ้งเตือน

[ อนุญาตการแจ้งเตือน ]
[ เริ่มเดินทาง ]  (disabled จนกว่าจะพร้อม)
```

รายการตรวจ:

- Location Services เปิดอยู่
- สิทธิ์ Location เพียงพอ
- Notification ได้รับอนุญาต
- การแจ้งเตือนมี sound setting ที่เหมาะสม
- จุดหมายและระยะเตือนถูกต้อง

หากเสียงอาจถูกปิด ให้ใช้ถ้อยคำว่า “การเตือนอาจไม่มีเสียง” แทนการซ่อนปัญหา

### 5.5 Active Trip — หน้าจอหลักของผลิตภัณฑ์

```text
┌─────────────────────────────┐
│ ● เปิดเตือนไว้แล้ว           │
│                             │
│       สถานีอโศก             │
│                             │
│      อีก 4.8 กม.             │
│        จะถึงอโศก             │
│  🔔 เตือนเมื่อเหลือ 1 กม.     │
│                             │
│   ───── mini map ─────      │
│   คุณ •────────────◉        │
│                             │
│ ✓ ตำแหน่งอัปเดตเมื่อครู่นี้   │
│ คุณล็อกหน้าจอได้             │
│                             │
│ [ หยุดการเตือน ]             │
└─────────────────────────────┘
```

ข้อกำหนด:

- ตัวเลขระยะเป็น visual hero
- ชื่อจุดหมายต้องอ่านได้แม้ใช้ Dynamic Type
- แสดง “อัปเดตล่าสุด” และคุณภาพตำแหน่งด้วยข้อความและสัญลักษณ์
- ปุ่มหยุดเป็น destructive secondary action และต้องยืนยันก่อนหยุด
- ไม่ต้องแสดง lat/lon ใน UI ปกติ แต่ให้มี Diagnostics ใน Debug build

### 5.6 Approaching — ใกล้ถึงแล้ว

เมื่อเข้าใกล้เขตเตือนชั้นใน:

- เปลี่ยน accent เป็นสีอำพัน
- ใช้ข้อความ “ใกล้ถึงแล้ว”
- เพิ่ม sensory feedback เมื่อแอปอยู่ foreground
- เพิ่มความถี่ในการอัปเดตตำแหน่งตาม trigger strategy
- ไม่ใช้ animation ต่อเนื่องที่รบกวนหรือกินแบตเตอรี่

### 5.7 Alarm — ถึงระยะเตือน

```text
┌─────────────────────────────┐
│                             │
│            🔔               │
│                             │
│       ใกล้ถึงแล้ว           │
│         สถานีอโศก           │
│                             │
│       เหลือประมาณ 850 ม.     │
│                             │
│ [ หยุดการเตือน ]             │
│ [ เตือนอีกครั้งใน 3 นาที ]    │
└─────────────────────────────┘
```

หากแอปไม่อยู่ foreground ระบบแจ้งเตือนของ iOS คือ UI หลัก เมื่อผู้ใช้แตะ notification จึงเปิดหน้าจอนี้

### 5.8 Recovery states

ใช้หน้า recovery ที่มีปัญหาเดียวและการแก้ไขเดียวที่ชัดเจน:

| สถานะ | ข้อความหลัก | การกระทำ |
|---|---|---|
| Location denied | ต้องใช้ตำแหน่งเพื่อเฝ้าจุดหมาย | เปิด Settings |
| Location unavailable | ยังหาตำแหน่งไม่ได้ | รอสัญญาณ / ลองใหม่ |
| Reduced accuracy | ตำแหน่งอาจไม่แม่นพอสำหรับระยะนี้ | อนุญาตตำแหน่งแม่นยำ |
| Notification denied | แอปไม่สามารถแจ้งเตือนเมื่อจอล็อก | เปิด Settings |
| Stale location | ตำแหน่งไม่ได้อัปเดต | แสดงเวลาล่าสุดและยังไม่ trigger |
| Wrong direction | ดูเหมือนกำลังออกห่างจากจุดหมาย | ตรวจจุดหมาย / เดินทางต่อ |

## 6. Trip state model

แยก lifecycle ของทริปออกจาก health ของระบบ:

```text
TripPhase
idle -> preparing -> tracking -> approaching -> alarm -> completed
                         |                         |
                         +-------> cancelled <-----+
```

```text
TripHealth
ready
locationUnavailable
staleLocation
reducedAccuracy
notificationUnavailable
wrongDirection
```

หนึ่งทริปอาจอยู่ใน `tracking` พร้อมกับ `wrongDirection` ได้ จึงไม่ควรนำสองแนวคิดนี้ไปรวมใน enum เดียว

## 7. Visual language

แนวทางหลักคือ **Native transit utility** หน้าตาควรเหมือนเครื่องมือเดินทางที่เปิดใช้ซ้ำได้ทุกวัน ไม่ใช่ concept screen ที่เน้นเอฟเฟกต์

- ใช้พื้นสีเทากราไฟต์และ system surface เป็นหลัก
- ตัด gradient, glow และ glass blur ที่ไม่ช่วยสื่อสถานะ
- ลดความโค้งของ card และใช้เส้นแบ่งบาง ๆ แทนเงาหนัก
- ใช้สีน้ำเงินเฉพาะสถานะกำลังติดตาม สีส้มเฉพาะตอนใกล้ถึง และสีแดงเฉพาะการหยุดหรือความผิดพลาด
- ให้แผนที่และตัวเลขเป็นจุดเด่น ไม่เพิ่มของตกแต่งที่แย่งสายตา

### สีเชิงความหมาย

- `tint/tracking`: system blue — เปิดการเตือนไว้และกำลังติดตาม
- `approaching`: system orange — ต้องเริ่มเตรียมตัว
- `alarm/destructive`: แดง — ใช้เฉพาะจุดที่ต้องการความสนใจทันที
- พื้นหลังและข้อความใช้ semantic system colors เพื่อรองรับ Light/Dark Mode

สีทุกสถานะต้องมาพร้อม icon และข้อความ เช่น `checkmark.circle` + “พร้อมเตือน” ไม่ใช้จุดสีล้วน

### Typography

- ชื่อหน้าจอ: system `.largeTitle` หรือ `.title`
- ระยะคงเหลือ: ตัวเลขขนาดใหญ่แบบ Dynamic Type และ monospaced digits
- สถานะ: `.headline`
- รายละเอียดสัญญาณ: `.footnote`/`.caption` แต่ยังต้องผ่าน contrast

### Motion และ haptics

- ใช้ animation สั้นเมื่อเปลี่ยน `tracking -> approaching`
- ใช้ haptic เฉพาะเริ่มเดินทาง, เข้า approaching และ alarm
- เคารพ Reduce Motion และการตั้งค่าการสั่นของผู้ใช้

## 8. Accessibility requirements

- รองรับ Dynamic Type รวมถึง accessibility sizes
- ปุ่มแตะต้องมีพื้นที่อย่างน้อยตามมาตรฐาน iOS
- VoiceOver อ่าน “อีก 4.8 กิโลเมตรจะถึงอโศก เตือนเมื่อเหลือ 1 กิโลเมตร” เป็นกลุ่มเดียว
- ไม่สื่อความหมายด้วยสีเพียงอย่างเดียว
- ระหว่างรถเคลื่อนที่ หลีกเลี่ยงข้อความเล็กหรือข้อมูลแน่นเกินไป
- ปุ่ม Stop และ Snooze ต้องมี label ที่ไม่กำกวม
