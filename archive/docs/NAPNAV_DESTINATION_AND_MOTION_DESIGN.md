## เป้าหมายของรอบนี้

ปรับ flow เลือกจุดหมายให้มีสองวิธีที่ชัดเจน เพิ่มหน้าเตรียมแอปตอนเปิด และวางระบบ animation ให้การเปลี่ยนสถานะต่อเนื่องขึ้น โดยยังคงแนวทาง **Calm Journey**: สงบ อ่านง่าย และไม่ใช้เอฟเฟกต์มากเกินจำเป็น

สิ่งที่ต้องทำมีสามส่วน:

1. เลือกจุดหมายด้วยการค้นหาหรือเลื่อนแผนที่ใต้หมุดกลางจอ
2. เพิ่ม startup loading ที่แสดงเฉพาะตอนแอปมีงานต้องเตรียมจริง
3. เพิ่ม motion และ feedback สำหรับการเปลี่ยนหน้าและการกดปุ่ม

## User flow

```text
เปิดแอป
  -> เตรียมข้อมูลเริ่มต้น (แสดงเฉพาะเมื่อจำเป็น)
  -> เลือกจุดหมาย
       -> ค้นหาสถานที่
       -> เลือกบนแผนที่
  -> ตรวจสอบจุดหมาย
  -> กำหนดระยะแจ้งเตือน
  -> เริ่มเดินทาง
```

ไม่ว่าผู้ใช้จะค้นหาหรือเลือกบนแผนที่ ผลลัพธ์ต้องมารวมกันที่ `Destination Preview` และใช้ flow หลังจากนั้นร่วมกัน

## 1. การเลือกจุดหมาย

หน้าเลือกจุดหมายมีตัวสลับสองโหมด:

```text
[ ค้นหาสถานที่ | เลือกบนแผนที่ ]
```

### 1.1 ค้นหาสถานที่

- แสดงช่องค้นหาและคำแนะนำจาก MapKit autocomplete
- เมื่อเลือกผลลัพธ์ กล้องแผนที่จะเคลื่อนไปยังตำแหน่งนั้น
- แสดงชื่อ ที่อยู่ และตำแหน่งบนแผนที่ก่อนยืนยัน
- ปุ่มหลักใช้ข้อความ `ใช้จุดหมายนี้`

### 1.2 เลือกบนแผนที่

โหมดนี้ไม่ใช้การแตะเพื่อวางหมุด หมุดเป็น overlay ที่อยู่กลางจอ ส่วนผู้ใช้ลากและซูมแผนที่ใต้หมุดแทน

```text
┌────────────────────────────┐
│                            │
│           หมุด             │
│             │              │
│             ▼              │
│       จุดกึ่งกลางแผนที่     │
│                            │
│                 ตำแหน่งฉัน  │
├────────────────────────────┤
│ สถานีศาลาแดง               │
│ ถนนสีลม เขตบางรัก          │
│                            │
│      ใช้ตำแหน่งนี้          │
└────────────────────────────┘
```

พฤติกรรมที่ต้องการ:

- ปลายหมุดต้องชี้พิกัดกึ่งกลางกล้องเสมอ
- ตอนเริ่มลากแผนที่ หมุดยกขึ้นเล็กน้อยและเพิ่มเงา
- ระหว่างเคลื่อนที่ แสดงสถานะ `กำลังเลือกตำแหน่ง…`
- เมื่อหยุดลาก หมุดวางลงด้วย spring สั้น ๆ
- รอประมาณ 300–500 มิลลิวินาทีก่อน reverse geocode เพื่อลดคำขอที่ไม่จำเป็น
- ถ้าผู้ใช้เลื่อนอีกครั้ง ให้ยกเลิกคำขอเดิมและยึดผลจากตำแหน่งล่าสุดเท่านั้น
- ระหว่างหาชื่อสถานที่ แสดงสถานะ `กำลังค้นหาชื่อสถานที่…`
- ถ้า reverse geocode ไม่สำเร็จ ยังยืนยันพิกัดได้ โดยใช้ชื่อสำรอง `จุดที่เลือกบนแผนที่`
- มีปุ่มเลื่อนกล้องกลับมายังตำแหน่งปัจจุบัน

สถานะภายในของ map picker:

```text
idle -> moving -> resolving -> ready
                            -> fallback
```

## 2. Startup และ loading

แยกการเปิดแอปเป็นสองชั้น:

### 2.1 Native Launch Screen

- ใช้พื้นหลังสีเดียวกับแอป
- แสดง `NapNav` และ `Trip Alarm` แบบเรียบ
- ไม่มี animation เพราะ Launch Screen ของระบบเป็นภาพคงที่

### 2.2 Startup View

แสดงเฉพาะตอนมีงานจริง เช่น อ่านการตั้งค่า กู้ทริปที่กำลังทำงาน หรือเตรียมสถานะเริ่มต้น

```text
         NapNav
       Trip Alarm

       ─────●─────

   กำลังเตรียมแผนที่
```

ข้อกำหนด:

- ถ้าแอปพร้อมภายในประมาณ 250–300 มิลลิวินาที ให้เข้าหน้าหลักทันทีเพื่อไม่ให้ loading กะพริบ
- ห้ามหน่วงเวลาเพื่อโชว์โลโก้โดยไม่มีงานจริง
- ข้อความเปลี่ยนตามงาน เช่น `กำลังเตรียมแผนที่` หรือ `กำลังกู้คืนทริป`
- ถ้าเตรียมข้อมูลไม่สำเร็จ ต้องมีสถานะผิดพลาดและปุ่มลองใหม่
- ไม่ขอ location permission บน Startup View ให้ขอเมื่อผู้ใช้เริ่ม action ที่เกี่ยวข้อง

สถานะระดับแอป:

```text
launching -> ready
          -> recoveringTrip -> ready
          -> failed -> retry
```

## 3. Motion design

ภาพรวมต้องสงบและเป็นธรรมชาติ ไม่ใช้แสงเรือง การเด้งแรง หรือ animation ต่อเนื่องที่รบกวนสายตา

### จังหวะหลัก

| เหตุการณ์ | Animation ที่เสนอ | ระยะเวลาโดยประมาณ |
|---|---|---:|
| Startup -> เลือกจุดหมาย | Fade พร้อม scale `0.98 -> 1` | 260–300 ms |
| สลับเป็นโหมดแผนที่ | ผลค้นหา fade/เลื่อนขึ้น หมุดและการ์ดปรากฏ | 220–280 ms |
| เลือกผลการค้นหา | กล้องเคลื่อนไปยังตำแหน่ง การ์ด crossfade | 400–500 ms |
| เริ่มลากแผนที่ | หมุดยกขึ้น 6–8 pt และเพิ่มเงา | 120–160 ms |
| หยุดลากแผนที่ | หมุดวางลงด้วย spring สั้น | 250–300 ms |
| Destination -> Alarm Setup | การ์ด/ชื่อจุดหมายเคลื่อนต่อเนื่อง แผนที่ crossfade | 280–320 ms |
| ปรับ Slider | วงรัศมีและตัวเลขเปลี่ยนต่อเนื่อง | 180–220 ms |
| กดเริ่มเดินทาง | ปุ่มเปลี่ยนเป็น progress แล้วเข้าสู่หน้าทริป | 280–320 ms |
| หยุดทริป | ยืนยันก่อน แล้ว fade กลับหน้าเลือกจุดหมาย | 240–280 ms |

ไม่ควรใช้ matched geometry กับตัว live map โดยตรง เพราะสถานะกล้องและ rendering เปลี่ยนได้ง่าย ให้เชื่อมเฉพาะการ์ด ชื่อจุดหมาย หรือองค์ประกอบคงที่ แล้วใช้ crossfade กับแผนที่

### ปุ่มและ feedback

- ปุ่มยุบลงเล็กน้อยตอนสัมผัส ไม่ต้องเด้งแรง
- ระหว่าง action แบบ async ให้ปุ่มแสดง `ProgressView` และป้องกันการกดซ้ำ
- ใช้ selection haptic เมื่อหมุดวางลงและได้ตำแหน่งใหม่
- ใช้ success haptic เมื่อเริ่มทริปสำเร็จ
- ใช้ warning/notification feedback ตอนเข้าเขตเตือนเพียงครั้งเดียว ไม่ทำ pulse วนตลอด

### Reduce Motion

ถ้าผู้ใช้เปิด Reduce Motion:

- เปลี่ยน slide, zoom และ spring เป็น crossfade
- ไม่ยกหมุดหรือทำ parallax
- การเปลี่ยนสถานะและข้อมูลต้องยังเข้าใจได้โดยไม่พึ่ง motion

## 4. โครงสร้างที่เสนอสำหรับการพัฒนา

- เพิ่ม `DestinationSelectionMode` สำหรับ `.search` และ `.mapPicker`
- แยกหน้าปัจจุบันเป็น `DestinationSearchView`, `CenterPinMapPicker` และ `DestinationPreviewCard`
- ใช้ candidate destination ชุดเดียวเป็น source of truth ของทั้งสองโหมด
- เพิ่ม `MapPickerState` สำหรับ `idle`, `moving`, `resolving`, `ready` และ `fallback`
- เก็บ reverse-geocode task แบบยกเลิกได้ และยอมรับเฉพาะผลล่าสุด
- เพิ่ม `AppLaunchState` สำหรับ startup, recovery และ failure
- ใช้ navigation state ที่ชัดเจน ไม่ผูก flow หลักไว้กับ animation completion
- รวม duration และ animation curve เป็น motion tokens เพื่อให้ทุกหน้ามีจังหวะเดียวกัน

## 5. ลำดับการทำงานรอบถัดไป

1. ตรวจโครงสร้าง `DestinationView` และ state ปัจจุบันก่อนแก้
2. เพิ่มสองโหมดเลือกจุดหมายโดยยังรักษา search flow เดิม
3. เปลี่ยนการแตะปักหมุดเป็น center-pin picker
4. เพิ่ม reverse geocode แบบ debounce และยกเลิกงานเก่าได้
5. เพิ่ม Launch Screen และ `StartupView`
6. วาง navigation transition และ motion tokens
7. เติม button state, haptics และ Reduce Motion
8. เพิ่ม previews และ tests ก่อนทดสอบ flow บน Simulator

## 6. Acceptance criteria

### Destination picker

- ผู้ใช้สลับระหว่างค้นหาและเลือกบนแผนที่ได้
- โหมดแผนที่ใช้หมุดคงที่กลางจอ ไม่ใช้การแตะเพื่อวางหมุด
- พิกัดที่ยืนยันตรงกับจุดปลายหมุดและกึ่งกลางกล้อง
- ลากแผนที่ต่อเนื่องแล้วผล reverse geocode เก่าไม่ย้อนมาทับตำแหน่งล่าสุด
- หากหาชื่อสถานที่ไม่ได้ ผู้ใช้ยังยืนยันพิกัดได้
- ทั้งสองโหมดส่งต่อไปยัง Destination Preview เดียวกัน

### Startup

- ไม่มี loading flash ตอนแอปพร้อมเร็ว
- กู้ active trip เดิมได้ก่อนแสดงหน้าหลัก
- startup failure มีข้อความที่เข้าใจได้และลองใหม่ได้
- ไม่มีการขอ permission โดยไม่มีบริบทระหว่างเปิดแอป

### Motion และ accessibility

- การเปลี่ยนหน้าหลักไม่มีการกระโดดของ layout
- ปุ่มที่กำลังทำงานกดซ้ำไม่ได้
- animation ไม่ขัดกับ system permission sheet หรือ lifecycle ของแอป
- Reduce Motion ใช้งาน flow ทั้งหมดได้ครบ
- VoiceOver อ่านชื่อสถานที่ สถานะการค้นหา และปุ่มยืนยันได้ถูกต้อง
